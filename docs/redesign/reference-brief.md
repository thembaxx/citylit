# Citylit reference and implementation brief

The design source is [the user's Claude conversation](https://claude.ai/share/fd51a657-84bd-4cd5-924c-6ede07fa78c4) and its supplied HTML, Markdown, handoff and Blender script. The complete researched HTML is retained as `reference-complete.html`; the supplied handoff is `reference-handoff.md`. The other supplied HTML files are earlier home/all-page iterations. The complete HTML is the primary visual reference, rather than the earlier all-page file that has empty data blocks.

The intended experience is a particle-field South Africa as the main interface, glowing city beacons, camera framing for cities and provinces, an amber/cream/ink palette, Fraunces and Manrope, restrained GSAP transitions and a rotating model stage for landmarks and places. Keep squircle controls and Phosphor icons. Retain actual catalog sources and working visit planning; do not replace the catalog with the prototype's draft entries or its placeholder privacy policy.

## Implemented adaptation

- A single persistent renderer serves the reference-style map, city/province framing and dedicated `/<city>/landmarks` and `/<city>/places` stages for all twelve cities. The original diorama explorer remains available through its existing links.
- Map beacons have keyboard-accessible names and a select alternative. The map fades behind scrolled content. Reduced-motion and essential-mode preferences suppress ambient choreography.
- The stage supports dragging and snapping, model picking, name chips, Prev/Next, source-linked practical facts, full-guide links and the same persistent day planner. Route lines illustrate selection order, not street directions. Cross-city and storage-failure guards are retained.
- Shared runtime colors follow the reference, including the loading/recovery screen, browser chrome, install manifest and downloaded guide. Self-hosted variable Fraunces supplies the correct display optical sizes; fonts and decoders load from this origin.
- Fifteen actual Blender-authored models replace the complete prototype's unbuilt model proposal. These are explicitly labelled illustrations rather than surveyed reconstructions. No Unity build was supplied or created; the optional flythrough proposal is not advertised as an available feature.
- Existing researched venue content, photographs, legal/privacy disclosures, correction reports, native planning and offline behavior remain functional. Interactive stage views are deliberately noindex; canonical city and venue guides retain their existing indexing and Markdown equivalents.

## Model authoring

Run `pnpm models:build` with Blender 4.3+ installed. Blender exports joined low-poly geometry; the pinned glTF Transform/Draco tooling compresses it, verifies a real decode and updates `public/models/stage/manifest.json`. `pnpm models:audit` verifies every committed model, its byte count, the required Draco extension, the 150 KiB budget and decoded vertex data. CI runs this audit without requiring Blender. The original nine featured city landmarks receive their own recognizable silhouettes; other entries use declared illustrative building/landscape types.

Models are about 5.5–13.4 KB each. Geometry is generated by `scripts/build-landmark-models.py`; `scripts/compress-stage-models.mjs` finalizes it. The local Draco runtime retains the Google/Three license notices in `public/draco/`. Models are downloaded only when their selected beacon or stage is shown. The hosting model/decoder endpoints remain public and cacheable; JavaScript eval remains blocked while the CSP permits WebAssembly compilation for the decoder.

## Production validation

The recurring production checker also verifies a landmark stage, the model manifest, a GLB signature and the local WASM decoder. Screenshots and viewport comparisons accompany the current project-root `design-qa.md`. `phase-one-qa.md` preserves the earlier implementation's QA history.
